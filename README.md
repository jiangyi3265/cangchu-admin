# cangchu-admin · 海外仓储管理后台

接手项目先读 [统一交接文件](https://github.com/jiangyi3265/cangchu-warehouse/blob/main/docs/HANDOFF.md)。本站已于 2026-11-16（America/New_York）切换到本若依前端和 Java 后端，使用用户确认的空白业务库；[部署文档](https://github.com/jiangyi3265/cangchu-warehouse/blob/main/docs/DEPLOYMENT.md) 记录当前发布和运维位置，密码另行私密交接。

基于若依 Vue 3 的仓储管理前端，为仓库和财务人员提供日常业务操作界面。

## 项目简介

本目录是仓储系统的若依管理前端，采用官方 RuoYi-Vue3 的登录、动态菜单、权限控制和页面布局，通过 JWT 调用独立 cangchu-backend 仓库的 Java 后端。仓储业务请求使用 `/warehouse` 接口，业务处理统一由 Java 服务完成。

入库页支持直接收货，以及隔离签收、检验、超收批准、分批上架和不合格报废。隔离货退供区展示批准数量、交接数量和未交接撤销数量；交接需要凭据和实物确认，批准、交接、撤销入口分别按权限显示。列表展示待处理实物数量，详情保留任务、检验、交接和上架记录。已结案原单可批准已知商品的迟到补单，明确管理费和 SKU 费规则，并查看原单关联与额外批准数量。补单操作断网后可刷新重试原请求。中英文与手机视图沿用若依组件，首页只请求当前岗位有权查看的数据。对应后端必须先执行全部编号迁移至 039。

未识别到货区展示实物描述、条码、到货凭据、隔离库位和数量去向，支持独立授权的登记、批准、执行与撤销。认领保留观察到的追踪信息；分批退供和报废必须确认实际处理。响应丢失后刷新，可用原请求恢复结果。仓储历史页面单独显示匿名实物，提示缺少商品资料时不能自动按零费用结算。

“店铺对接”提供 WooCommerce 连接配置、按页拉取、订单待审与拉取历史。配置仅超级管理员维护，员工按客户/仓库范围读取和拉取。密钥不回显、不写入浏览器恢复记录；配置保存或拉取丢失响应后，可查询原请求。待审页面显示付款、退款及已有发运等异常，并提供来源设置、SKU 对照、实时核验和仓库接单。接单响应丢失后恢复同一订单；接单结果可直接打开订单管理继续分配、扫码和装箱，实物交运与平台写回仍待接通。

“快递发运”提供 DPD 英国连接、申请记录和原始面单下载；订单详情可查询实际账号服务、申请面单并核对断线请求。已建单仅补取缺失面单，结果不明不能重复创建，面单取得不会自动扣库存或回传平台。页面支持中英文及手机宽度，真实账号与实物交运仍待验收。

## 技术栈

- JavaScript、Vue 3.5、Vue Router 4、Pinia 3
- Element Plus 2、Axios 1
- Vite 6、Sass
- 官方 RuoYi-Vue3 3.9.2 底座，固定来源提交见 [UPSTREAM.md](./UPSTREAM.md)

依赖版本以 `package-lock.json` 为准。本地已使用 Node.js 24 验证安装、开发服务和构建。Node.js / npm 是 Vue 前端工具链，清理旧 Node 后端后仍需保留。

## 快速启动

先按 [Java 后端目录](https://github.com/jiangyi3265/cangchu-backend) 的说明启动后端、MySQL 和 Redis。前端不创建默认管理员账号，不预填或保存登录密码；使用后端配置的本地账号和验证码登录。

```bash
# 在 cangchu-admin 仓库根目录执行
npm ci
npm run dev
```

访问 `http://127.0.0.1:5174`。浏览器请求 `/dev-api`，Vite 将其转发到 `http://127.0.0.1:18080` 并移除 `/dev-api` 前缀。登录、官方系统管理和仓储接口都经过同一个 Java 服务。

```bash
npm run build:prod
npm run test:warehouse
```

构建产物位于 `dist/`。正式运行需要 Web 服务提供静态文件及 Vue Router 的路径回退，并将 API 前缀反向代理到 Java；Vite 的开发代理不会包含在构建产物中。

`public-config.js` 提供不含密钥的默认标题和 `/dev-api` 前缀，干净检出即使没有任何 `.env` 文件也能构建。需要更换前缀时，可在本地配置 `VITE_APP_BASE_API`；此值会写入浏览器代码。密码、数据库连接和平台密钥只能配置在服务端，不能使用前端环境变量保存。

## 已接入的仓储页面

| 页面 | 当前操作 |
| --- | --- |
| 仓储概览 | 读取 Java 的统计和模块状态 |
| 基础资料 | 客户、商品、仓库、库位类型、库位的查询、新建、修改和删除；使用记录版本防止覆盖他人修改 |
| 库存作业 | 查询库存、人工入库、扣减、移库；这些人工操作不自动生成费用 |
| 入库管理 | 新建/修改预报，分批收货到指定库位，批次/串号/有效期记录，按件/SKU 入库计费，确认柜/托/箱数量和工时后结案；短收结案仅限管理员批准 |
| 订单履约 | 手工建单、暂停/恢复、分配库存、逐件条码/串号扫描、拣货确认、多箱实测装箱、撤销更正、取消及人工出库；展示库存分配与作业历史 |
| 库存盘点 | 按客户与库位冻结、逐行实盘、差异原因、补录盘盈、提交复核/退回重盘、审核调整和取消解冻；空输入不会当成零，未知响应保留原请求 |
| 退货处理 | 原发运关联、隔离签收、检验、分批上架/报废和结案；批次/串号来源可查，支持断线后原请求恢复、双语和窄屏表格 |
| 数据范围 | 超级管理员管理账号的客户和仓库范围；无授权不表示拥有全部数据，保存使用版本核对 |
| 财务计费 | 订单量/渠道阶梯价、仓库拣货费、周期规则和账单项目类型；手工费用、账单草稿及确认/撤销、周期收费、订单量阶梯及历史仓储费的预览结算、库位仓储单价、历史库存/来源查询、结算历史与费用快照 |

入库详情另提供“收货记录更正”：选择原行、追踪移库来源、填写多录数量与凭据，经批准后由另一人明确确认执行。原始收货保留，更正历史和执行原因可查，断线后可恢复原请求。财务页的“费用复核待办”显示对应原费用，支持填写理由保留收费或创建关联调整，并直接进入现有调整审批流程；两处均提供中英文界面。

七类基础资料页提供“批量导入”和“导出 Excel”。按新增或更新下载模板，上传 XLSX / UTF-8 CSV 后查看行号、错误及展开的字段变更，再确认整批写入。空单元格保留默认值或原值，`__CLEAR__` 明确清空；更新须保留导出中的 id / _version。当前用户可查看最近 100 次通过预检的记录并撤销未提交批次；丢失返回结果时，刷新后保留原请求恢复入口。导出沿用关键词筛选，按每批最多 500 行下载，财务字段按权限隐藏。

新增“供应商管理”和“销售渠道”菜单，需后端菜单迁移 033。共享资料仅超级管理员可新增、编辑、删除和导入；授权员工可查看和导出。入库预报可选供应商，详情和迟到补单保留当时名称；手工订单可选销售渠道，列表、详情和渠道计费使用同一名称。未选渠道时归为 Manual，清空选择可恢复此分类。停用项不能用于新关联，已有单据仍保留原值；渠道选择不会授权或连接店铺。

库存、入库、订单和财务提交使用请求编号。请求结果不明确时，浏览器保留原编号和原内容，重试同一笔操作；不会将超时显示为成功。入库及订单扫码/装箱支持刷新后的原请求恢复，未确认结果前暂停新提交。要求扫码的订单需扫齐后拣货、全部装箱后出库；更正记录保留原因，包裹记录含装箱明细和实测重量尺寸。财务金额使用十进制文本输入和服务端计算结果，页面不以 JavaScript 浮点数重新汇总金额。

其他平台适配、实物交运与平台回传、自动结算及其他尚未完成的流程，需按 Java 后端的实际能力继续迁移和验收。当前实现不代表已完成与真实店铺、快递或原系统的正式切换，也不承诺与原系统全部功能一致。

财务页新增“历史仓储复核”：选择完整账期，按凭据分配未识别实物、补充当时缺失的商品计费资料、预览与保存，再由另一人批准。已批准内容进入周期结算，审批岗位无须获得商品维护权限。批准后资料锁定，已结算显示费用编号；断线恢复沿用原操作与对应权限。复核不改变实物库存或原始历史。

## 中英文

登录页、主要导航、仓储页面及 Element Plus 控件支持中文和英文，右上角可切换，选择保存在当前浏览器。官方系统管理的部分页面仍保留上游中文文案；业务数据、用户自定义名称及服务端错误内容不会被自动翻译。

财务页面的“调账与贷项”支持原费用加载、复核预览、独立批准/执行、撤销批准、历史追溯和贷项打印。费用及账单行可直接发起调整；只具执行权限的人员也能恢复结果未知的原执行请求。已确认账单保留原内容，贷项单不表示现金退款或已同步会计平台。
